# Черновик DoD команды

**Версия:** 0.3
**Владелец:** Quality & Safety
**Согласование:** approve от каждой роли в PR ветки `lab1-quality-initiation`

Каждый критерий проверяется одним из трёх способов: **есть/нет**, **число**, **ссылка**. Критерий, который нельзя проверить так, в DoD не попадает.

## 1. Общее для всех ролей

| Критерий | Проверка |
|---|---|
| Работа сдана отдельным PR от роли | ссылка на PR |
| Ветка названа `lab1-[role]-initiation` | есть/нет |
| Заголовок PR: `Lab1: [Role] — Initiation Deliverables` | есть/нет |
| CI на PR зелёный | ссылка на прогон |
| Термины в документах совпадают с `docs/glossary.md` | число расхождений = 0 |
| Готова презентация «Я понял проект как…» | ссылка |

## 2. Product / VO

| Артефакт | Критерий | Проверка |
|---|---|---|
| `docs/prd.md` | Назван один основной сегмент | есть/нет |
| | Болей от 3 до 5, у каждой есть идентификатор (P1, P2…) | число 3–5 |
| | У каждой боли указано, когда она возникает, и последствие | число болей без этого = 0 |
| | North Star: формулировка, целевое значение и формула подсчёта | есть/нет |
| | Рядом с North Star — предел задержки (с) и стоимости операции (₽) | два числа |
| | Описаны границы MVP: что входит и что не входит | есть/нет |
| | PRD прочитан всей командой | отметка от каждой роли, число = 4 |
| `docs/hypotheses.md` | Гипотез не меньше 3, у каждой есть идентификатор (H1, H2…) | число ≥ 3 |
| | У каждой — условие подтверждения и условие опровержения с числовым порогом | число гипотез без порога = 0 |
| | У каждой — способ проверки | число гипотез без способа = 0 |
| | У каждой указано, какую боль (P1…) или ограничение PRD она проверяет | число гипотез без указания = 0 |
| `docs/insights.md` | Проведено не меньше 3 интервью с представителями сегмента, карточки заполнены | число ≥ 3 |
| | В каждой карточке есть отметка по H1–H3 | число карточек без отметки = 0 |
| | В сводке для H1, H2, H3 посчитана доля и записан вывод | три числа |
| | Каждый инсайт ссылается на карточки интервью | число инсайтов без ссылки = 0 |
| | Заполнен раздел «Что меняем в PRD по итогам интервью» | есть/нет |
| `docs/glossary.md` | Есть термины «требование», «пункт чек-листа», «версия чек-листа», «согласованный пункт», «заказчик», «исполнитель» | есть/нет |
| | Описаны четыре состояния требования: актуально, отменено, конфликтует, требует уточнения | число состояний = 4 |
| | Для одного понятия один термин («правка» или «требование», не оба) | число синонимов = 0 |
| | У каждого термина — определение и пример | число терминов без примера = 0 |
| | Согласован вслух | отметка в PR от каждой роли, число = 4 |
| `docs/brief.md` | Читается за 2 минуты | число слов ≤ 300 |
| | Описаны оба слоя результата: сводка переписки и чек-лист | есть/нет |
| | Есть ссылка на PRD | ссылка |

## 5. Quality & Safety

| Артефакт | Критерий | Проверка |
|---|---|---|
| `docs/quality/success-criteria.md` | У каждого критерия — число и способ подсчёта | число критериев без способа = 0 |
| | У каждой боли из PRD — строка «что значит решает» | число болей без строки = 0 |
| | Значения из PRD перенесены без изменений: North Star ≥ 80 %, задержка ≤ 10 с, стоимость ≤ 5 ₽ | три числа |
| | Пороги из описания темы перенесены без изменений: recall ≥ 0,85, precision ≥ 0,90, точность состояния ≥ 0,85 | три числа |
| | Целевые значения согласованы с Product | approve от Product |
| | Указано, что меряется автоматически с лабы 3 | есть/нет |
| `docs/quality/golden-dataset-plan.md` | Назван источник для 30–50 пар | есть/нет |
| | Описаны происхождение, версия, формат записи, владелец | есть/нет |
| | Примеров не меньше 10 | число ≥ 10 |
| | У каждого примера указаны тип случая и боль PRD | число примеров без указания = 0 |
| | Есть примеры с двумя и более порциями переписки | число ≥ 2 |
| `docs/quality/dod-draft.md` | Каждый критерий — есть/нет, число или ссылка | число непроверяемых = 0 |
| | Согласовано с командой | approve от каждой роли, число = 4 |
