# Черновик DoD команды

DoD - список признаков, по которым команда считает артефакт готовым. Каждый критерий проверяется одним из трёх способов: есть/нет, число или ссылка. Если критерий нельзя проверить так, в DoD он не попадает.

## Общее для всех ролей

| Критерий | Проверка |
|---|---|
| Работа сдана отдельным PR от роли | ссылка на PR |
| Ветка названа `lab1-[role]-initiation` | есть/нет |
| Заголовок PR: `Lab1: [Role] — Initiation Deliverables` | есть/нет |
| CI на PR зелёный | ссылка на прогон |
| Термины в документах используются так, как в `docs/glossary.md` | число расхождений = 0 |
| Готова презентация "Я понял проект как..." | ссылка |

## Product / VO

| Артефакт | Критерий | Проверка |
|---|---|---|
| `docs/prd.md` | Назван один основной сегмент | есть/нет |
| | Болей от 3 до 5, у каждой есть номер (P1, P2 и так далее) | число от 3 до 5 |
| | У каждой боли указано, когда она возникает, и последствие | число болей без этого = 0 |
| | У North Star есть формулировка, целевое значение и формула | есть/нет |
| | Рядом с North Star указаны предел задержки в секундах и предел стоимости обработки в рублях | два числа |
| | Описаны границы MVP: что входит и что не входит | есть/нет |
| | PRD прочитан всей командой | отметка от каждой роли, число = 4 |
| `docs/hypotheses.md` | Гипотез не меньше 3, у каждой есть номер (H1, H2 и так далее) | число >= 3 |
| | У каждой есть условие подтверждения и условие опровержения с числовым порогом | число гипотез без порога = 0 |
| | У каждой описан способ проверки | число гипотез без способа = 0 |
| `docs/insights.md` | Проведено не меньше 1 интервью с представителем сегмента | число >= 1 |
| | Номера и формулировки гипотез совпадают с `docs/hypotheses.md` | число расхождений = 0 |
| | По каждому интервью записан статус гипотез, которые проверяются интервью | число гипотез без статуса = 0 |
| | Каждый инсайт ссылается на интервью, из которого он получен | число инсайтов без ссылки = 0 |
| | Есть раздел о том, что меняется в PRD по итогам интервью | есть/нет |
| `docs/glossary.md` | Есть термины: требование, правка, задача, пункт чек-листа, версия чек-листа, проверено исполнителем, требует уточнения | есть/нет |
| | Различие между требованием, правкой и задачей явно зафиксировано, неоднозначных синонимов нет | есть/нет |
| | Состояния пунктов в документах команды совпадают с глоссарием | число расхождений = 0 |
| | У каждого термина есть определение | число терминов без определения = 0 |
| | У ключевых терминов есть пример: требование, правка, задача, недостающая информация, вопрос на уточнение, пункт чек-листа | число ключевых терминов без примера = 0 |
| | Глоссарий согласован вслух | отметка в PR от каждой роли, число = 4 |
| `docs/brief.md` | Читается за 2 минуты | число слов <= 300 |
| | Описаны блоки результата: суммаризация, чек-листы, "Что нужно уточнить" | есть/нет |
| | Есть ссылка на PRD | ссылка |

## Delivery

| Артефакт | Критерий | Проверка |
|---|---|---|
| `README.md` и структура репозитория | Другой участник поднял проект по README с нуля | отметка в PR, есть/нет |
| `compose.dev.yml`, `.env.example` | Dev-окружение стартует без ошибок | есть/нет |
| | В `.env.example` перечислены все переменные, секретов нет | число секретов = 0 |
| `.github/workflows/ci.yml` | CI проходит на открытом PR | ссылка на прогон |
| `docs/deploy.md`, URL в README | Hello-world открывается по публичному URL | ссылка, код ответа 200 |

## Quality & Safety

| Артефакт | Критерий | Проверка |
|---|---|---|
| `docs/quality/success-criteria.md` | У каждого критерия есть число и способ подсчёта | число критериев без способа = 0 |
| | Для каждой боли из PRD написано, что значит "продукт её решает" | число болей без строки = 0 |
| | Значения из PRD перенесены без изменений: North Star >= 80%, задержка <= 10 с, стоимость <= 5 руб. | три числа |
| | Пороги из описания темы перенесены без изменений: recall >= 0,85, precision >= 0,90, точность состояния >= 0,85 | три числа |
| | Целевые значения согласованы с Product | approve от Product |
| | Указано, что меряется автоматически с лабы 3 | есть/нет |
| `docs/quality/golden-dataset-plan.md` | Назван источник для 30-50 пар | есть/нет |
| | Описаны происхождение и версия данных, формат записи, владелец датасета | есть/нет |
| | Примеров не меньше 10 | число >= 10 |
| | У каждого примера указаны тип случая и боль PRD | число примеров без указания = 0 |
| | Есть примеры с двумя и более пачками сообщений | число >= 2 |
| | У примеров, построенных по интервью, указан номер интервью | число таких примеров без номера = 0 |
| `docs/quality/dod-draft.md` | Каждый критерий проверяется как есть/нет, число или ссылка | число непроверяемых = 0 |
| | Согласовано с командой | approve от каждой роли, число = 4 |
